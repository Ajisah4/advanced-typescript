# Type-Only Imports

<EpicVideo url="https://www.epicweb.dev/workshops/advanced-typescript/3-modules/type-only-imports" />

👨‍💼 We want to organize shared types in their own module so the rest of the
code can import them cleanly.

```ts
// types.ts
export type Book = { title: string; pages: number }

// index.ts
import { type Book } from './types.ts'
```

🐨 Open <InlineFile file="types.ts" /> and <InlineFile file="index.ts" /> and:

1. Move the `User` and `Product` types into `types.ts` and export them
2. Import them in `index.ts` using type-only import syntax (no runtime value
   imports from `types.ts`)
3. Keep the local `user` / `product` values and display helpers working
4. Export `displayUser` and `displayProduct` from `index.ts`

<callout-info>
	When importing **types only** (not values), use `import { type X }` syntax.
	This tells TypeScript (and Node.js) that these imports are purely for type
	checking and should be erased at runtime. This is required when running
	TypeScript natively with Node.js.
</callout-info>

Completion check: both display helpers remain callable and are exported from
`index.ts`, with no runtime value imports from `types.ts`.
